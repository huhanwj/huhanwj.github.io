# The Draw — IERG2060 Tutorial 3

A student-facing random draw at `/ierg2060-t3/`. It is unlinked from the homepage and marked noindex. There is no grading, score display, or SID display. Attendance and participation reports live in the private Google spreadsheet.

Click **Draw one student** to reveal one student with a short card animation and enter answer mode. Enter a whole number of minutes (1–180), then press **Start**. Start saves the exact student, question number and class attendance first; the countdown begins only after that save is confirmed. Double clicks cannot submit another draw. Failed or uncertain saves retain the same request and frozen duration for **Retry Start**.

**Redraw** replaces an unsaved student for the same question without counting their participation. It selects another eligible student and is disabled if only one eligible student remains. Once Start saves the draw, Redraw is disabled. **Next student** ends the saved student’s timer and draws the next student. Question numbers advance from confirmed draws for the selected class date and can be adjusted before a draw. They are independent of participation rounds. Students cannot repeat in a participation round; everyone must complete the first round before the second begins. Missing students keep their unfinished turn; if all remaining students are absent, drawing pauses. Historical multi-student batches remain readable and unchanged.

The countdown uses a saved deadline, so background tabs do not slow it down. Reloading in the same browser restores the active timer without saving again. If a reload confirms a save whose response was previously lost, the page asks for Start before beginning the timer. The timer itself is browser-local; participation and attendance remain in Google Sheets. Time reaching zero displays **Time is up** and waits for the instructor to select Next student. Unsaved previews are memory-only and show a warning before leaving the page. Reduced-motion users receive an immediate reveal.

The presentation guide prominently asks students to behave respectfully and stay quiet while others are presenting.

**Absent today** accepts an empty string or positive roster numbers separated by ASCII commas, for example `10,21,26`. Spaces, Chinese commas, leading zeros, duplicate numbers, and unknown numbers are rejected. Clear the field for a class with no absences. Choose **Class date** (defaults to the Hong Kong calendar date), then click **Save attendance** to record that date without drawing. **Start** records both the selected student and that date’s attendance. Saving the same date corrects its record; other dates remain intact. Switching dates restores that date’s saved absences, or an empty unsaved list. Leaving the absent field blank and saving explicitly records everyone present. Drawing alone does not save attendance.

After the owner connects, **Records ↗** opens the private spreadsheet. **出勤记录** has one student per row and one saved date per column, with 到场 / 缺席 and totals. **讲题记录** lists names, class dates, batch/question positions and participation rounds. **学生名单** summarizes participation. Internal storage tabs are hidden. These views regenerate from the saved app records; maintain attendance through the website, not by editing generated cells. Draw settings → **Refresh record sheets** rebuilds these views without changing saved progress. Old participation flags remain labeled as historical; missing class dates or attendance are never inferred.

**Google Sheets sync** uses the two public endpoint addresses in `cloud-config.js`, so a fresh browser starts in account-protected cloud mode. Draw settings use the fixed class connection and expose a Reconnect button, not editable endpoint fields. These URLs are not credentials. The administrator deployment allows only the deploying Google account; the backend also checks the actual signed-in account against its explicit allowlist on every admin action. There is no TA key or identity value supplied by the browser. The student QR contains only this site's signup address and the current room ID. The signup page always uses the configured student endpoint; a URL parameter cannot redirect submissions to another deployment. The endpoint remains visible in browser network requests because this is a static site. [Backend and setup instructions](google-apps-script/README.md). The Google owner must authorize and deploy both endpoints before cloud sync works. Existing key-based deployments must be archived or updated; changing source alone does not revoke old deployed versions. The private roster snapshot and storage spreadsheet remain Restricted. The original shared teaching sheet is not edited. The snapshot includes only Tutorial 3 numbers, names and participation flags, copied once by the owner; future cloud operations use the private copy. Browser-side anonymous Google Sheet imports have been removed; use the authenticated cloud connection or a local CSV/JSON file.

The first connection previews initialization from existing browser progress (with refreshed names), or the source sheet if no local progress exists. Initialize explicitly. Later connections restore canonical cloud state. Draws display as previews before Start; uncertain saves retain the same request ID and exact result for retry, and cannot be cancelled until their outcome is known. Another device's newer revision is loaded on conflict. Cloud mode disables replacement CSV imports; Refresh names updates names without changing turns. **Download backup** downloads a JSON backup of confirmed progress.

**Bonus round** in cloud mode stores signups and its winner in Google Sheets. Students scan the QR and enter only their roster No.; the service deduplicates that number. Close registration before drawing. Reloading preserves entries and results. Students self-report their No.; this is not identity verification. In local-only mode, the existing PeerJS connection remains available; keep the host tab open, and use manual entry if the classroom network blocks it. Bonus does not change formal participation rounds.

CSV import retains only roster No., optional Name, and whether Question 1 / Question 2 have numeric entries. Zero also means a previous turn. Scores, SID and other columns are discarded. The Apps Script backend reads selected source columns and never reads SID data cells. No class roster is shipped in this public repository. Previous browser backups still load; missing names can be refreshed when connecting Google Sheets. Local CSV/JSON import replaces browser progress, so use a backup before importing.

Serve locally with `python3 -m http.server`. There is no build step. Check layout in a browser, and selection/import invariants with Node. AGENTS.MD requests Python unittest discovery; this static repository has no tests directory.

Vendored MIT libraries: PeerJS 1.5.5 and qrcode-generator 1.4.4. Their licenses are included in `vendor/`.

Security boundaries: both HTML pages use a Content Security Policy that allows scripts only from this site and restricts frames and other resource origins. The public API accepts only bounded registration fields, returns round availability and registration receipts, and does not return names, winners, roster lists, duplicate flags, or raw internal errors. Closed-round receipt retries still reveal whether a supplied number previously joined; self-reported registration is not identity verification and the TA checks numbers in person. Anonymous traffic can still consume Apps Script quotas; this architecture does not provide strong denial-of-service protection. A secret scan of committed application files is not a guarantee that no credential has ever been exposed.

The source spreadsheet ID is no longer embedded in backend source; optional first-time bootstrap reads a server-side SOURCE_ID property. Existing private roster snapshots do not read the source sheet. Already-published addresses remain in Git history; hiding or deleting current source cannot revoke Google access. The private STORE_ID stays in Script Properties, and the private spreadsheet must remain Restricted.
